# I18N — StoryForge Internationalization

> Maintainer guide for the i18n system (react-i18next, 3 locales, 37 namespaces).

## Architecture

```
src/i18n/
├── index.ts          # initI18n(), useDomainT(), getT(), SUPPORTED_LANGS
├── i18next.d.ts      # Typed resources (37 namespaces × 3 locales)
└── locales/
    ├── pt-BR/        # Default language (37 JSON files)
    ├── en/           # English (37 JSON files)
    └── zh-CN/        # Chinese source of truth (37 JSON files)
```

- **Stack**: i18next + react-i18next + i18next-browser-languagedetector + i18next-resources-to-backend
- **Loading**: `import.meta.glob('./locales/*/*.json')` → resourcesToBackend (lazy per-namespace chunks, auto-precached by vite-plugin-pwa)
- **Detection**: localStorage `sf_lang` → navigator.language → pt-BR default
- **Fallback chain**: `pt-BR → [zh-CN]`, `en → [zh-CN]`, `zh-CN → []` (source of truth), `default → [pt-BR]`
- **Preload set** (loaded at init): common, nav, shared, errors, errors-lib, layout (layout preloaded since the P0 cold-load fix — workspace chrome must never render raw keys)

## Usage Patterns

### React components (typed)
```tsx
import { useDomainT } from '../../i18n'

function MyPanel() {
  const { t, ready } = useDomainT('settings') // own domain only
  if (!ready) return null
  return <span>{t('aiConfig.title')}</span>
}
```

### Non-React code (stores, lib, hooks)
```ts
import { getT } from '../../i18n'

const t = getT()
throw new Error(t('errors-lib:ai.networkError'))
```

### Cross-namespace reads
- Components: own domain + `common:` prefix (auto-layered by useDomainT)
- Stores/lib: `errors:`, `errors-lib:`, `common:defaults.*` via getT()
- **Forbidden**: reading another component domain's namespace

### Persisted default names (A4 pattern)
Default entity names created at runtime are translated at creation time:
```ts
name: getT()('common:defaults.newInventoryItemName')
```
These become user-editable content after creation.

### Dual-use labelKey (data catalogs)
Data catalogs (codex `BUILTIN_CATEGORIES`, node-authoring catalog, `GENRE_OPTIONS`, prompt seeds) carry `labelKey` / `descriptionKey` / `optionKeys` fields; components resolve them via `t(key, chineseFallback)`. The inline Chinese fields REMAIN — they are AI prompt payloads and/or persisted defaults (A4). When a user manually edits a label/options, clear the key field so manual text wins.

### List formatting / separators
Never hardcode `join('、')` / `join('；')` or fullwidth `（）：` wrappers in UI strings:
- Components: `new Intl.ListFormat(lang, { type: 'conjunction', style: 'short' })` with `useDomainT(ns).lang` (memoize per lang)
- Stores/lib: `getShortListFormatter(lang)` from `src/i18n/index.ts`
- Wrapper punctuation (e.g. `（{{count}}）`) belongs in locale keys with locale-natural punctuation

### Persisted runtime strings (chat messages, run labels, activity logs)
Translate at creation via `getT()`; persisted rows keep their creation-locale text (expected behavior — do not change stored schemas).

## Adding a New Key

1. Add the key to **all three** locale JSONs (zh-CN first — it's the source of truth)
2. Use the key in code via `t('key')` (typed — tsc will fail until the key exists in pt-BR)
3. Run `npx vitest run tests/registry/i18n.test.ts` to verify parity

## Adding a New Locale

1. Create `src/i18n/locales/{lang}/` with all 37 JSON files
2. Add the language to `SUPPORTED_LANGS` in `src/i18n/index.ts`
3. Update `i18next.d.ts` resource type
4. Update registry test CLDR plural categories
5. Add language option to LanguageSelector

## What NOT to Translate (LEAVE categories)

- AI prompt payloads (system/user message content fed to AI models)
- Code comments
- console.log/warn/error messages
- Regex patterns / keyword classification data
- Persisted Chinese story content (manuscript data)
- `.includes()` checks on data keys
- simulation/runtime.ts domain validation (244 keys reserved for future extraction)
- rag-library.ts field labels (RAG document context for AI)
- retrieval.ts / context-snapshot.ts AI markdown builders
- Exported manuscript artifacts (text-export)

## Testing

- **Registry tests** (`tests/registry/i18n*.test.ts`): 3-locale parity (CLDR-normalized), fallback chain, detector mapping, interpolation/plurals, static ns-usage discipline, backend loading, computed-key group resolution (`i18n-computed-keys.test.ts`)
- **E2E** (`tests/e2e/language-switch.spec.ts`): 3-way round-trip + persistence + zero raw `nav.*`/`contentType.*` leaks after switching; `tests/e2e/workspace-cold-i18n.spec.ts`: cold-mount workspace, zero raw keys in all 3 locales
- **Unit test setup** (`tests/setup.ts`): synchronous zh-CN init with all namespaces eager-loaded
- **Plurals**: en/pt-BR use `_one`/`_other`; zh-CN uses `_other` only (never add zh `_one`)
